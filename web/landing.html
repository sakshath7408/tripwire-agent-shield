How it works

One tool call in, one verdict out.

  1. 1

    Your words are the instructions

    The task you type is the only trusted text in a session.

  2. 2

    Everything the agent reads is data

    Files, web pages, emails, tool descriptions. Tripwire records every address, host, path and command they contain, and where it came from.

  3. 3

    Every tool call is checked

    If a send, pay, fetch or run uses something you never typed, that is the injection. Allow, ask, or block, with a one-line reason.

Features

Built for real agents, not just the demo.

  • Provenance tracking

    Every value that shows up in tool output is tagged with its source. Use one you never typed, and the reason names the file it came from.

  • Shell analysis that decodes payloads

    Commands are parsed into an AST, not regex-matched. Base64, hex, bash -c, eval, pipes to a shell and nested runners are unwrapped and judged.

  • Permission roles

    Each agent gets a tool list in plain YAML. An inbox assistant that asks for a shell is blocked, unknown tools go to a human.

  • Asks only when it matters

    Balanced autonomy decides the obvious cases on its own. Money, passwords, risky commands and anything after hidden instructions still stop for you.

  • Learned "always allow"

    One click teaches a narrow rule: same tool, same action, same target. Never for money, credentials, or in a session that saw hidden instructions.

  • Paired dashboard, no admin key

    A browser is paired only through a person at the terminal. There is no control credential on disk for an agent to find and use.

  • Tamper-evident audit chain

    Every task, output, verdict and click is one hash-chained, signed row. Edit one and tripwire audit verify names it. Sub-agents land in one tree.

  • MCP gateway with signed tool pins

    Put any MCP server behind the proxy. Tool descriptions are pinned on first use, so a rug-pull or a poisoned description is caught.

  • Claude Code hooks

    tripwire install claude adds a PreToolUse hook. It never widens Claude Code's own permissions, and it denies when the daemon is down.

  • Hardened mode

    tripwire install claude --sandbox puts the agent's shell in an OS sandbox, no root needed. tripwire harden runs the daemon as its own OS user, so nothing running as you can stop or replace the guard.

Install

Four commands. Python 3.12 and uv.

  1. git clone --depth 1 https://github.com/sakshath7408/tripwire-agent-shield
    cd tripwire-agent-shield    a shallow clone skips the old demo videos in the history
  2. uv tool install .puts tripwire on your PATH
  3. tripwire servekeep it running; it prints a one-time dashboard link
  4. cd ~/your-project
    tripwire install claude    guards Claude Code in that folder. --user guards every project; mcp-proxy wraps any MCP server

Nothing leaves your machine. The daemon listens on 127.0.0.1 only and never does a DNS lookup. Full README
