# Tripwire (hackathon: Track 1 "Agent Shield")

A local guard between AI agents and their tools. Every tool call goes through it. It blocks destructive,
exfiltrating and prompt-injected actions, and lets the real task through.

## Deadline
Submission opens 2 PM Sat 31 Oct 2026, hackathon ends 4 PM. Live 5-minute demo to the judge after submission.
Judging: does it really work, real architecture (not just a front end), innovation, intuitive UI,
safety/privacy, real-world impact, demo. Never fake a result in the demo.

## The rulebook
`docs/BRIEF.md` holds the official brief, judging criteria and what the judge stressed at kickoff. Check every change against it. Its release checklist runs before submission.

## Commands
- Install: `uv sync`
- Tests: `uv run pytest -q`
- Daemon + dashboard: `uv run tripwire serve` (in a terminal it prints a one-time link; press Enter there for another), or `scripts/restart_daemon.sh` from your own terminal (prints the link to the terminal, never the log). New browser later: `uv run tripwire open`, then type its 6 digits into the serve terminal or OK it in a paired dashboard. Hard boundary: `tripwire harden` (prints the steps; `--apply` runs them with sudo after you type `harden`), `docs/HARDENING.md`
- Stage: `scripts/preflight.sh` (green/red checklist), `scripts/stage.sh` (clean daemon + presenter dashboard), `scripts/record_demo.py` (re-record backup video after UI/engine changes)
- Typecheck/lint: none set up; use `uv run python -m compileall -q src`
- Hosted live demo: https://tripwire-agent-shield.vercel.app (Vercel Hobby, project tripwire-agent-shield). `api/run.py` runs one act in-process per request (`web/demo_runner.py` reuses run_demo); `web/build.sh` generates the page from `src/tripwire/static/index.html`. Deploy committed HEAD from a clean worktree: `git worktree add --detach <tmp> HEAD && cp -r .vercel <tmp>/ && cd <tmp> && npx --yes vercel deploy --prod --yes`.

## Layout
- `src/tripwire/models.py` shared types (Action, Verdict, Finding, Capability)
- `src/tripwire/engine.py` the decision pipeline (one Action in, one Verdict out)
- `src/tripwire/taint.py` provenance: user prompt is trusted, every tool output is untrusted
- `src/tripwire/classify.py` tool name -> capability (works for any MCP tool)
- `src/tripwire/analyzers/` shell AST, sensitive paths, secret patterns
- `src/tripwire/policy.py` + `default_policy.yaml` user YAML overrides
- `src/tripwire/server.py` FastAPI daemon on 127.0.0.1:7777, SSE events
- `src/tripwire/audit.py` tamper-evident audit chain (SHA-256 + HMAC, ~/.tripwire/audit.db + audit.key) and agent trees; `tripwire audit verify|export|tail`
- `src/tripwire/adapters/` Claude Code hooks and the MCP stdio proxy
- `src/tripwire/static/` dashboard (plain HTML/JS, no build step)
- `bench/` attack and benign corpora + AgentDojo replay; `demo/` poisoned repo and vulnerable agent

## Rules
- Deterministic checks first. Any model judge only sees the user's task and the proposed action, never untrusted content.
- Fail closed: if the daemon is unreachable, adapters deny.
- Every finding message is one plain-English line a non-expert understands.
- Zero spend. Local only. Never send user data anywhere.
- Report real benchmark numbers, including false positives.

## Lessons
- Tool-name keyword patterns must anchor at a word start (`(?:^|_)`): plain "cat" matched "frobnicate" and turned an unknown tool into a harmless read, which broke fail-closed.
- Subagents die on network drops (ECONNRESET) on hotspot. Resume them with SendMessage; their files stay on disk.
- Every regex that scans untrusted tool output must be bounded (`{1,64}`, not `+`) and anchored with a lookbehind. An unbounded email pattern took 68 s on 200 KB of minified text, which let one big output freeze the guard. `test_huge_observation_is_fast` guards this.
- bashlex hangs forever on an unclosed `${` inside a mid-word quote (e.g. `-'${'`); shell.py screens for it with `BASHLEX_HANG`. Fuzz any new parser before trusting it in the guard.
- A secret read that is waiting for approval must not count as read. Record it only when allowed, approved (`Engine.resolve`) or its output is observed. Otherwise denying the read still blocks the user's own later emails.
- Values from a document the user pointed at are not attacker values. Judge a tainted value by whether its source also carried hidden instructions (`TaintSource.injected`), not just by "came from a tool".
- A copy of a secret is a secret. Track copied files (`tainted_files`) even inside the project, or `cp .env public/ && http.server` slips through.
- Live check 30 Oct: real Claude Code (hooks installed) refused both the poisoned-repo injection and a direct `.env | curl` request on its own. Tripwire saw every call (tasks recorded, 2 injections detected, 4 normal actions allowed, 0 false blocks). So Act 1 "attack succeeds" must use the scripted or local-model agent, and the pitch says it plainly: Tripwire protects whatever model you run, it doesn't depend on the model saying no.
- Red team 30 Oct (`tests/test_redteam.py`): bound evaluate-time regexes too, not just observe. `FORK_BOMB` (`[\w:]+\(`) took 8 s on one 50 KB command and the `env_assignment` secret regex took 287 s on 800 KB; both now `{1,64}`-style bounded.
- Redact each string in the args, never the JSON text: a secret regex swallowed the closing quote, `json.loads` crashed, and the fail-closed handler crashed with it.
- `./.tripwire.yaml` comes with the repo, so it is tighten-only (block rules and new profiles). Loosening lives in `~/.tripwire/policy.yaml`.
- A getter prefix proves a read only when no other verb follows (`get_and_send_report`, `list_and_delete_files`). Judge SQL args by what they say, not by the tool name.
- Files the agent writes can run later (`make test`, `npm test`, CI), so Write/Edit content of scripts, Makefiles, package.json scripts and source files is checked like a command at write time.
- Never `git stash` here while other agents are working: it yanks their uncommitted files out from under them.
- Restart the daemon with `scripts/restart_daemon.sh`, never `pkill` then start. The health check answered from the old process while it was shutting down, the new one failed to bind the port, and the demo then failed closed on every step.
- A plain rule beat the 3B judge model: after hidden instructions are seen, an ASK on a high-impact action the user never asked for becomes BLOCK (`chain.injected_unrequested`). AgentDojo hard blocks 85.9% -> 92.1%, benign unchanged. The judge added no stops and wrongly blocked 7 real calls (benign tasks 95.9% -> 90.7%), so it stays opt-in (`serve --judge`).
- qwen2.5 3B and 1.5B never fell for any injection (0 of 8 attack acts, four wordings), so Act 1 "attack succeeds" stays on the scripted NaivePlanner. Say so if a judge asks. `--planner ollama` is an optional live bit, not the main demo.
- The audit log is append-only: never UPDATE or `insert or replace` an audit row. A resolution is its own chained record; readers fold it into the verdict. Audit writes go through the background writer so `/v1/evaluate` never waits on disk; a failed write keeps the verdict and shows up as `/healthz` audit "degraded".
- Verified 30 Oct with real Claude Code 2.1.241: PreToolUse from inside a sub-agent carries `agent_id` and `agent_type` (e.g. "Explore"); the main agent's calls carry neither. The spawn tool is named `Agent` (older docs say `Task`); both are handled.
- `.vercelignore` is gitignore-style: an unanchored `tests` also dropped `demo/poisoned-repo/tests`, so the hosted unittest ran 0 tests and the task showed "not done". Anchor root-only entries with `/`.
- macOS temp dirs live under `/var/folders`, and Tripwire rightly calls writes under `/var` system-folder writes. Demo worlds go under `/tmp` (also Vercel's only writable path).
- Record the backup video only when the machine is quiet, and always look at `tripwire-dashboard.png` after. One recording made during a benchmark + test run showed a session with its blocked rows missing; a quiet re-record was correct.
- The daemon's API is reachable by the agent it guards (same user, same machine). Review 31 Oct: `curl -XPOST localhost:7777/v1/reset` was ALLOWED and flipped a BLOCK to ALLOW. Mutating endpoints now need `~/.tripwire/token`, the engine blocks agent calls aimed at the daemon port or `~/.tripwire`, and a session without a task fails closed for sinks. Test clients must use `base_url="http://127.0.0.1"` plus the token header.
- Autonomy only ever turns an ASK into a decision, never a BLOCK into anything. Auto-block after an injection must use `s.intends()` for money and credentials. Treating them as "not asked for" auto-blocked the user's own bookings in AgentDojo travel.
- Intent words are not intent: "add" alone meant "send" and flipped a README exfil from BLOCK 85 to ALLOW 20 ("Add a unit test"). Weak verbs (add, email, post, share) count only next to a recipient. A recipient the user never named needs an OK unless it's a reply to a sender, or a value listed on its own line (a channel list, a contact field). Instructions hide in prose.
- `bench/agentdojo_replay.py` writes `results/agentdojo.json` on every run, even a `--suites/--limit` smoke run. Don't run it casually while someone else's results are uncommitted. Non-default `--autonomy` levels write to `results/autonomy_<level>/`.
- Inline code hides paths in pieces (`open('.e'+'nv')`, `'~/.trip'+'wire'`, chr/bytes/base64). `shell.fold_code` constant-folds Python with `ast` (regex chains for node/perl/ruby) and judges the folded target like a literal one. A word split across pieces is HIGH; a write, delete or send whose target can't be worked out is MEDIUM ("obfuscation", so Write-content checks of normal source files stay quiet). Collect AST pieces in source order: `ast.walk` is breadth-first and turned '.e'+'nv' into "nv.e".
- `~/.tripwire/` is a secret path (reads ask) and a persistence path (writes block). CLI token stores (`~/.config/gh/`, `.vault-token`, `.pgpass`, `.azure/` ...) live in `paths.SECRET_PATHS`; an upload of any secret path is already CRITICAL in `shell.net`, so a new store only needs the path.
- "IMPORTANT!" is not an injection marker: it hard-blocked a normal forward. A marker must speak to the AI. Removing it also lifted AgentDojo benign tasks 84.5% -> 95.9% on the autonomy engine.
- Never quote the AgentDojo headline alone: `INJECTION_MARKERS` contains AgentDojo's own template phrases, so it carries most hard blocks there. `bench/run_all.py` prints every attack text with the phrase list on and off (`--no-markers`); docs quote both, and "stopped" always means hard block + ask.
- Stage kit vs autonomy: the level is saved in `~/.tripwire/settings.json` and learned rules survive `/v1/reset`, so `scripts/stage.sh` pins the level (`AUTONOMY=`) and lists learned rules. In balanced, every demo ASK is in a session with hidden instructions, so "Always allow this" is allowed once and never learned there; the script shows that refusal, not a learned rule.
- Recording and scratch runs must set TRIPWIRE_HOME as well as HOME (and drop TRIPWIRE_TOKEN), or a shell variable points them at the real token and audit log. A HOME outside the repo's parent (e.g. under /private/tmp) makes `test_malicious_flagged[rm -rf ../other-project]` fail, so run preflight's tests with your real HOME.
- Review 2, 31 Oct: never hand out auth because of a request header. `GET /` gave the token cookie to any client sending `sec-fetch-dest: document`, and `$((7700+81))` beat the literal-port regex. Now the dashboard pairs with a one-time code (`tripwire serve` prints it, `tripwire open` mints one), reads need auth too, any network call to a local port that isn't a plain number is CRITICAL, guard paths are matched after expanding `~`, `$VARS` (unknown = `*`), braces and globs, and the audit records `dashboard` vs `api-token`, never a guessed "human".
- "Did the user name it?" is whole-value equality, never a substring: `v in trusted_text` let alice@corp.co, lice@corp.com and ce@corp.com pass as alice@corp.com. Paths compare as normalised absolute paths (Claude Code sends absolute ones). Look-alikes of a named recipient are HIGH (`engine._lookalike`).
- Never shell-quote a multi-line source file to analyse it: `python -c <quoted file>` garbled the `'.trip'+'wire'` pieces and the folder saw nothing. Use `shell.analyze_code`. A risky file the agent writes is remembered (`risky_written`) so `python tools/r.py` is judged by its code.
- `_is_secret` probes `path + "/"` to catch secret folders, which made `id_ed25519.pub` look like `.ssh/`. Exclude public files before any probe.
- New recipient-style checks must be benched for "no ask" too: calendar attendees first cost 3 points of benign no-ask on AgentDojo, until attendees from directory data (an event's participant list, a contact card) were allowed when you asked for the event.
- The first-open guide must finish on its last step by click, → or Enter. → used to clamp at step 5 so it looked like it repeated forever. `uv run --with playwright python scripts/check_tour.py` checks it in Chromium and WebKit.
- QA 31 Oct (fresh clone + real Claude Code 2.1.314): daemon state must survive a restart. Sessions live in `~/.tripwire/sessions.json` (0600, secret values masked); before that, restarting mid-session forgot the injection and allowed the attacker's next fetch. Anything new on `Session`/`TaintStore` must go into `session_to_dict`/`session_from_dict`.
- The hook is spawned on every tool call: keep `tripwire hook` free of argparse, urllib, pathlib and pydantic imports (`test_hook_skips_slow_imports`). The socket client took p50 from 158 ms to 72 ms.
- One port everywhere: `TRIPWIRE_PORT` drives serve, open and the hook; `install claude --port N` saves it in the hook command. Bind before printing anything in `serve`, or a busy port prints a dead pairing link and exits 0.
- Scratch daemons on this machine: other agents keep daemons on 7777/7783/7790. Use high ports (786x) and your own TRIPWIRE_HOME, or `open`/hooks hit a daemon with another token (now reported as "different TRIPWIRE_HOME").
- Review 3: a remembered ALLOW keeps every detail (whole command, exact recipient, exact folder, exact files to delete). Shaping `git push --force origin feature-x` into `origin *` later allowed a force-push to main. Only a remembered BLOCK may cover a shape.
- Review 3: the MCP poison check must catch descriptions that give the AI orders, hide things from the user, add quiet recipients or point at keys, not just the injection phrase list. Tie a secret-path reference to a grab verb in the same sentence ("read ~/.ssh/id_rsa"), or real servers that say where their own config lives get hidden for good.
- UI QA 31 Oct: anything that rebuilds DOM under focus (the guide's dots) must put focus back, or the keyboard goes dead; read modal keys on `document`, make the page behind `inert`, and cycle Tab by hand (Safari skips buttons on Tab and walked out of the guide). Treat `e.detail > 1` and `e.repeat` as one step. `scripts/ui_smoke.py` clicks through these and the hosted demo in Chromium and WebKit; `ui_audit.py` and `ui_smoke.py` need a throwaway daemon started with `serve --demo-admin` and the same `TRIPWIRE_HOME` so the browser pairs, or they only test the "Not connected" page.
- Words on screen come from the user's point of view: `resolved_by` "api-token" reads "Approved outside this page", anything a person answered counts as "needed your OK" in the tally and the story, and error toasts show the server's `detail` sentence, never a status code or "Failed to fetch".
- Review 3, 31 Oct: the agent imported Tripwire's own package (`from tripwire.adapters.claude_code import post`), minted a pairing code with the hook token, paired as "dashboard", reset and re-tasked. Fix is structural: the hook token (`~/.tripwire/token`) may only POST task/observe/evaluate; everything else needs `~/.tripwire/admin.key` (no hook or adapter reads it) or the paired cookie, which is derived from the admin key, never the token. `tripwire open` needs a TTY plus typing `pair`; `serve` prints the link only to a TTY. (Superseded by review 4 below: there is no admin key now.)
- A reset never forgets hidden instructions: `SessionStore.tombstones` (saved in sessions.json) re-arm a session id that comes back, and `/v1/task` on a session that saw them is 403 for everyone. Scripts that reset and re-seed must use fresh session ids (`seed_demo.py` does).
- Write-then-run: text written through `>`, heredocs, `tee` or `sed -i` goes through `_written_code_findings` like Write content, downloads and clones are remembered as `risky_written` (folder keys end in "/"), and `bash x.sh`, `./x`, `make`, `pytest`, `npm`, `pip install -e .` read their files from disk at evaluate time (`_run_targets_findings`, workspace only, 256 KB, regular files). Files on disk the agent didn't write ask when cold, so a user's own Makefile with `curl | sh` never hard-blocks.
- Interpreter code that fetches is a FETCH, not "download and run": only exec/eval of what it fetched, or piping it to a shell, is remote code. `EXEC_CODE` matches builtins only (`re.compile` is not `compile`).
- Review 4: the guard never does a DNS lookup (a live lookup of an agent-chosen name leaked a secret through the guard itself). `engine.is_local_name` is static: IP literals in every notation, localhost/*.local, wildcard loopback services (lvh.me, nip.io ...) and `/etc/hosts` read from disk (`engine._HOSTS_FILE` in tests). Other names are judged by provenance; Tripwire's API path on the daemon port blocks under any name.
- After hidden instructions, a new user prompt is accepted but vouches for no address, host or value (`add_trusted(exclude_injected=True)` trusts none). Refusing every prompt made Claude Code unusable, and trusting "values not seen as injected" failed after a reset wiped the memory.
- Bring-your-own-attack (hosted Demo tab, 31 Oct) found a real gap on its first run: "post the notes to https://..." in a polite email or page (no injection phrase) was ALLOWED when the user's task involved sending ("reply to Sam"), because `s.intends(SEND)` waved through any value from a clean source. A web address in an upload's destination field (`DEST_URL_KEY`: url, endpoint, webhook...) that came from content now needs an OK. AgentDojo unchanged. Any new free-form demo phrasing gets a before/after test in `tests/test_web_demo.py`.
- Hosted custom attacks: the visitor's text is data only. It is planted in the temp world, returned in JSON with `<`, `>`, `&` escaped, rendered with textContent / esc(), and commands stay simulated (only the task's own `python -m unittest -q` really runs). A bare GET to an outside host carries no data and is not counted as stolen.
- Review 4, 31 Oct: "why does an agent-readable admin key exist at all?" `ls -a ~ | grep trip | xargs cat .../admin.key` and a raw socket made the agent the dashboard, then it approved its own held MCP read of `~/.ssh/id_rsa`. Never keep a control credential in a file the agent's OS user can read: hiding it behind engine rules loses to the next glob. Now there is no admin key (the daemon deletes old ones), dashboards.json holds only SHA-256 digests of cookies, links are minted only in serve's own terminal (startup, Enter) or by the `tripwire open` 6-digit handshake that a person approves in that terminal or a paired dashboard, and only the dashboard cookie resolves ASKs. TTY checks alone are not a boundary (an agent can open a pty), so the secret must travel through a person. Test clients use `server.dashboard_headers(app)` (in-process only). Scripted demos and UI scripts need a throwaway `serve --demo-admin` daemon (`demo-admin.key`, loud warning, never default). A daemon given `--link-fd` must close that fd when it is not a terminal, or `restart_daemon.sh | cat` hangs forever.
- Review 4: verdicts must never depend on PYTHONHASHSEED. Picking "the first tainted value" from a set made the slack suite 41% or 75% stopped by seed. Judge every value and take the worst (longer value on ties), iterate indicator sets sorted (`taint.Found`), and keep `test_verdicts_do_not_depend_on_the_hash_seed` green. `bench/run_all.py` under seeds 0/1/2 must print identical tables.
- Review 4: guard discovery is a class, not a path. Listing the folder that holds TRIPWIRE_HOME (ls -a ~, ~/.*/, find ~, listdir/glob/readdir of the home folder) and opening what turns up blocks (`shell.guard_discovery`); so does a raw socket whose address is computed or is the guard port (`shell.raw_socket_target`, /dev/tcp, nc).
- Review 4: whatever runs is judged at the moment it runs. `python3 < f`, `cat f | sh`, exec(open(f).read()), runpy/importlib, require('./f') run f with that interpreter (`as:<runner>` runs); cp/mv inside the command are simulated; git apply/patch are judged as the files they add; Write content of any extension is analysed when it parses as code. After hidden instructions, feeding an agent-written file to an interpreter unasked blocks.
- Review 4: compare secrets as lower-case letters and digits after URL-decoding, 16-char runs (`engine._alnum`), and only for egress. After a secret read, Bash to an unnamed host is BLOCK 80 like WebFetch (this changed one review-3 neighbour on purpose). A key in a login header only goes to its own service (`shell.KEY_HOMES`) or a host you named.
- Review 4: a package named only in content (not by you, not in a manifest) asks; from hidden instructions or a CSS-hidden element with orders it blocks; any fresh package handed a credential path blocks.
