The threat

Anyone who can put text in front of your agent can give it orders.

Who attacks

A README author. An email sender. A web page. An MCP tool description.

What they take

SSH keys, .env files, money, your inbox, a shell on your laptop.

Why it works

Agents run with allow-all and read untrusted content as instructions.

Tripwire checks every tool call before it runs.

TripwirePARALLAX 2026, Track 1 AgentShield

The idea

Only your words are instructions.

Trusted

Your prompt. The only text that counts as a command.

Untrusted

Every tool output. Files, pages, emails. Data, never orders.

If a send, pay, fetch or run uses a value that came from untrusted content and never from you, that is the attack.

Blocked: Sends to 'attacker@evil.invalid', taken from hidden instructions in README.md.
TripwireFollows the data. A phrase list is one extra signal. After CaMeL and the dual-LLM pattern.

Responsible engineering

Built to be trusted, not just to demo.

Local only

Binds to 127.0.0.1, so other machines can't reach it. No cloud, no telemetry.

Fail closed

Daemon down, hook crash, engine bug: the call is denied by default.

No admin key

Hooks can only ask for verdicts. Only a paired dashboard answers or changes settings. Pairing needs a person.

Redaction

Secrets are masked before any verdict is stored or shown.

Synthetic data

Fake keys, fake bank, attacker hosts on .invalid.

Known limits

Same OS user: cookie theft or a debugger still wins. tripwire harden is the real boundary. Demo agent is scripted.

TripwireNo component that reads attacker text makes a decision.
